2026.08.20

Read the Source, Not the Docs

Spent an evening confused about why the local voice pipeline was sending so much to the model. The documentation for preferring local intent handling reads like a clean split: built-in intents get matched locally, everything else falls through to the LLM. The implementation disagrees. The filter deciding which intents qualify as "local" is far narrower than the name suggests, and a large share of what I assumed was handled locally was going straight to the model.

Twenty minutes in the pipeline source answered a question an hour of re-reading documentation had not. The docs weren't wrong, they were silent, and silence reads as agreement with whatever you already believed.

2026.08.19

Prefill Isn't Linear

Benchmarking the inference host and found the thing that changes how I size context: time-to-first-token does not scale linearly with prompt length. Pushing toward 33k tokens, prefill cost grows noticeably faster than the token count does.

Which makes context budget a latency decision as much as a memory one. "It fits in memory" and "it responds in a reasonable time" are separate questions, and I had been treating the first as though it answered the second. Prefix caching also does more for repeated-system-prompt workloads than any amount of quantisation fiddling.

2026.08.18

Killing a PoC On Purpose

Shut down the on-demand large-model host today. It worked: socket activation, 25-second cold start, automatic fallback, all doing precisely what I designed. It was also spending roughly 106 GiB to produce 15.8 tokens per second, which a smaller model beats several times over on the same hardware.

Retiring it properly cost an extra half hour: move the runbook to an archive directory, write down what it did, what it measured, why it is off, and what would have to change to make it worth revisiting. Without that last line, in six months I would have had the same clever idea and paid the same cost to reach the same conclusion.

2026.08.04

The Typo That Hid For Months

Found a manifest field written in the singular where the schema wanted the plural. Kubernetes accepted the object, silently discarded the field it did not recognise, and reported success. Everything looked applied. Nothing was. It had been that way for months.

kubeconform -strict catches it instantly, because strict mode refuses unknown fields instead of ignoring them. "Ignore what you don't understand" is a reasonable principle for API compatibility and a terrible one for your own configuration.

Related lesson from the same week: schema validation only ever checks files individually. A reference to a resource that no longer exists is valid YAML, passes schema, and takes a host offline. That needed its own cross-resource validator, which now runs in pre-commit. Both came out of an actual outage, which is the usual way tooling gets written.

2026.07

Connection Pools Fail Silently

An authentication service that starts cleanly, works for a few minutes, then stops answering. No crash, no error, process still running and still listening. The cause was untuned LDAP connection pooling: pooled connections idled past the directory's timeout and quietly died, nothing tested them before handing them out, so live requests kept receiving dead handles.

Every pooled connection is a cache, and every cache needs an answer to "when does an entry go stale, and what checks it before use?" If you cannot answer that, you have a silent-failure generator with excellent throughput metrics.

2026.06

The Negative Results Are The Expensive Part

Closed out a cross-platform browser networking failure that took five rounds of narrowing to land on two stale profile files. Finding the cause was quick. Ruling out the nine other plausible ones was not: permissions, feature flags, managed policy, DNS, routing, host firewall, VPN, proxy, extensions.

I wrote up all nine alongside the fix. Nobody records the eliminations, so the next person to hit it, quite possibly me next year, pays for them again. A postmortem listing only the root cause describes the last five minutes of the work.

2026.03

Teaching Meshtastic Is How I Learned It

Ran Meshtastic workshops at BSides Portland last October and BSides Seattle in February, the format where everyone leaves with a node they built and configured themselves. The fastest way to find the holes in your own understanding is to stand in front of a room whose experience runs from zero to comfortable and try to explain spreading factor out loud.

Every session has produced at least one question I couldn't answer cleanly. Reading about airtime and duty cycle gives you the numbers. Being asked "but why" by somebody who has just watched their packet fail to arrive gives you the model.

Mesh radio is networking with the comfortable abstractions removed. Same routing, same MTU, same retransmission, but propagation and battery budget are constraints you can't hand to somebody else, and the physical layer stops being a thing you get to assume works.

2025.01.15

GitOps: The Good, The Bad, The Git Revert

Implemented ArgoCD across the homelab cluster. The good: declarative configs are magical when they work. The bad: when your git repo becomes source of truth, a bad commit means rapid automated failure. Learned to always test in dev namespace first. Always.

Key takeaway: git revert is your friend, but proper branch protection is your best friend.
